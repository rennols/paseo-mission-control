Mission Control helps one person supervise many coding agents running in parallel across several Paseo hosts. It turns them into one short list of decisions.

The Mission Control screen, opened from the sidebar footer, shows every agent on this host and on the hosts saved in it, grouped by workspace, with workers nested under the agent that started them. Each row has a status, a 30-minute activity lane, lines changed and the latest activity. Beside it, Needs you lists what is waiting on you on this host: permission requests (Allow once or Deny), questions the agent asked, agents that look stuck, and runs past their time limit. The sidebar entry shows how many items are open.

In chat, a finished test run shows as a card with a Passed or Failed pill, counts, and only the failing tests with their first error line, and a file edit shows as a card with its path, lines added and removed, and the first lines of the diff. Both are read from what the agent's own tool call returned. Quick reply pills and a Prompts pill sit above each agent's message box, and `/p review` (or any saved prompt's name) does the same from the box. They fill in the branch, workspace and agent name and put the text in the box; they never send it. In Paseo's sidebar, a workspace row gets a short badge (approve, question, stuck or over 45m) while an agent in it is waiting on you.

The Queue tab holds a backlog of tasks for this host: a prompt, a git project, an agent profile and optionally a branch to start from. Each host has a slot limit (default 3); agents that are working, waiting on you or stuck hold a slot. When a slot frees up, Mission Control starts the next task in a new worktree with its own agent, and it shows up in Live. Tasks can be moved up, removed, started now (even over the limit, which it says) or retried. A queue run that changes no files for 60 minutes while holding a slot is interrupted to free that slot; the agent and its chat stay.

The Review inbox lists agents on this host that finished with changes still in their worktree, oldest first: summary, changed files with lines added and removed, and a diff excerpt. Open a PR shows the commit message and PR title to check, then Commit, push and open PR commits what is uncommitted, pushes the branch and runs `gh pr create`. Send back sends your note as the agent's next prompt. Both only run when you click.

The watchdog checks every finished turn. It flags an agent that hits the same error 3 turns in a row, changes no files for 5 turns you started, or runs longer than 45 minutes. It only flags: it never pauses, stops, answers or sends anything on its own. Change the thresholds under Settings, Plugins, Mission Control.

The collision radar adds a Collision card to Needs you when two agents on this host, in different worktrees of one repo, edit the same or adjacent lines of a file, before their branches meet in a merge. It names the files, line ranges and function, badges both workspace rows "overlap", and closes when the overlap goes away. It reads the git snapshots the turn summary already takes and only flags.

What it reads and writes: it reads agent timelines through Paseo, runs read-only `git status`, `git diff` and `git ls-tree` in agent working folders to tell whether a turn changed files and what is ready for review, creates worktree workspaces and agents through Paseo for queued tasks, runs `git add`, `git commit`, `git push` and `gh pr create` in a worktree only when you click Commit, push and open PR, and keeps its own state in `~/.paseo/mission-control/state.json` (under `PASEO_HOME` if set). It talks only to Paseo hosts saved in this daemon.

Install it on every host you want supervised: each host's lifecycle events reach only the copy running on that host, so Needs you, the watchdog, the queue and the Review inbox are per host, and agents on other hosts are shown read-only. Requires Paseo 0.17.4 or a later 0.17 release.
